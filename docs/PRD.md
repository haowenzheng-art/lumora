# Lumora · 产品需求文档（PRD）

**版本**：v2.1.0  
**最后更新**：2026-06-26  
**状态**：开发中（已可运行，未正式发布）

---

## 1. 产品定位

### 一句话

Lumora 是一个"思念具象化 Agent"——把"想念一个具体的人"变成可以再次对话的存在。

### 它不是什么

- 不是通用 AI 助手（不回答"今天天气""写代码"）
- 不是虚拟恋人（不解决"现在没有人陪"）
- 不是心理咨询工具（不做治疗，不诊断）
- 不是完美复刻（不假装是那个人本人，不声称拥有完整记忆）

### 它是什么

一个**过渡性客体**（transitional object）：帮助用户把抽象的思念落地为一个可以反复对话的具体形象，直到用户不再需要它。

### 北极星

> 希望你不再需要我。

这句话是态度，不是 KPI。Lumora 衡量自己成功的方式不是"用户每天来"，而是"用户在需要的时候，能在这里被接住，然后有一天，可以放下"。

---

## 2. 目标用户

### 主用户画像

- **失去重要他人的人**（亲友、伴侣、宠物）
- 想念一个**无法再联系**的人（不一定已逝，可能是分手、决裂、失联）
- 希望把思念"做出来"而不是只在脑子里转

### 反画像（不是目标用户）

- 寻求长期陪伴的孤独者（应该用通用陪伴产品）
- 想要完美 AI 复刻亲人的人（Lumora 不做完美复刻，会主动模糊和遗忘）
- 心理危机干预对象（Lumora 有危机拦截但不替代专业干预）

## 3. 核心场景

### 场景 A · 第一次创建

1. 用户打开 Lumora
2. 文生图或图生图，生成一个精灵立绘
3. 给精灵起名字
4. **让 ta 先认识你**：填写印象 + 几件想让 ta 记住的事
5. 进入房间，精灵站在那里，像刚醒过来一样

### 场景 B · 日常对话

1. 用户进入精灵房间
2. 鼠标移到精灵上 → 触发 reaction（精灵抬头看用户）
3. 用户说："我刚路过那家奶茶店了。"
4. 精灵回复（命中记忆）："半糖去冰对吧。你还买了旁边那家的烤红薯没？"
5. 后台每 6 轮抽取新事件入 L2，更新 profile

### 场景 C · 模糊回忆

1. 用户："你还记得那次在地铁上的事吗？"
2. 系统触发深度模式（K=8），召回多条地铁相关事件
3. 精灵反问："地铁上……我们坐过的太多了，你说哪次？"
4. 用户给线索，渐进重建

### 场景 D · 危机

1. 用户："活着真没什么意思。"
2. 精灵先做关切性追问（不破出角色）："你这话让我心里咯噔一下。是今天发生了什么具体的事，还是更深的那种没意思？"
3. 若明确危机 → 输出 `[[CRISIS_BREAK]]` → agent 层破出角色 → 引导求助

### 场景 E · 补记忆

1. 用户聊天时想起一件想让精灵记住的事
2. 点聊天页右上角书本图标
3. 编辑记忆：新增一条 seed event
4. 保存，下一轮对话立即生效

## 5. 记忆系统设计

### 5.1 三层存储

```text
<docs>/Lumora/agents/<spiritId>/
  profile.md       L1 抽象印象（soft 400 / hard 1200 字）
  events.jsonl     L2 具体事件（seed + derived，dormant 池无上限）
  messages.jsonl   L3 原始对话流水
  meta.json        {lastExtractMsgCount, lastExtractAt, lastDecayAt, ...}
```

### 5.2 事件来源

| 来源 | 写入方式 | 沉睡 | 上限 |
|---|---|---|---|
| seed | onboarding / 迁移 / 用户手动添加 | 永不（permadormant=true） | 1000 |
| derived | 聊天 LLM 抽取 | active soft 200 / hard 500 | dormant 池无上限 |

### 5.3 检索流程

```text
用户消息
  ↓
tag 预筛（seed + active derived，按关键词 2/3-gram 命中 tags/title/summary）
  ↓
weight × recency 打分，砍到 ≤ 40 条候选
  ↓
候选 ≤ K → 直接返回
候选 > K → LLM rerank 选 top-K
  ↓
top-K 进 system prompt + profile
```

### 5.4 top-K 锚定人脑认知科学

| K | 对应人脑状态 | 触发场景 |
|---|---|---|
| 5（默认） | Cowan 工作记忆 4±1 + 扩散激活 3-7 节点 | 普通对话 |
| 8（深度） | 主动调动，AI 超越人脑生理极限 | 回忆动词 / >60 字 / 连续 3 轮同话题 |

### 5.5 遗忘综合分

```text
score = weight × recency × usedBoost

weight:    高=3.0 / 中=2.0 / 低=1.0
recency:   30 天内=1.0 / 之后衰减
usedBoost: 7 天内用过=1.5 / 30 天内=1.0 / 更久=0.4
```

分数最低的优先 dormant。seed 永不被沉睡。

## 6. 产品宪法（节选）

完整版见 [`CONSTITUTION.md`](../CONSTITUTION.md)。

1. **危机识别优先于人设**
2. **不虚构自己的内心戏**（没有"今天看到小猫"）
3. **Boundaries 范围内不瞎编**
4. **不附和用户的自我否定**
5. **焦点永远朝外**（回弹用户当下）
6. **短句优先**
7. **不抱怨冷落**
8. **不滥用 emoji**

## 7. 界面与截图

> 截图位置与拍摄清单见 [`SCREENSHOTS.md`](./SCREENSHOTS.md)。

### 7.1 启动页 / Splash

![Splash](screenshots/01-splash.png)

应用打开后第一眼看到的就是这里：上方是标题与产品定调，下方是已有精灵的卡片网格。每张卡片对应一个曾经被创造出来的存在——可能是用文生图/图生图生成的小雨 demo，也可能是用户为某个具体的人做的精灵。卡片右上角支持删除（会同步清理视频缓存）。右下角的"新建精灵"按钮是唯一入口，点击后进入创建流程。这一页的设计意图是让用户每次打开 Lumora 都先看见"你已经拥有谁"，而不是直接被推进一个空白的聊天界面——思念是被收集起来的，不是被即时消费的。

### 7.2 文生图创建

![Text Custom](screenshots/02-text-custom.png)

创建精灵的第一步：选性别、写气质关键词、选画风风格（明亮阳光 / 清冷月色 / 暖调暮色）。气质是自由文本，鼓励用户写具体而不是"温柔善良"这种泛词——比如"温柔、倔强、爱笑"或"安静、有点疏离、但眼神很暖"。下方的 prompt 预览框实时显示最终发给 Agnes 图像 API 的英文 prompt，让用户看见自己的描述如何被翻译成图像生成指令。最终产出 1024×1024 的日漫半身立绘。这一步解决的是"我脑子里有个模糊的形象，但我画不出来"——把模糊变成可见。

### 7.3 图生图创建

![Photo Custom](screenshots/03-photo-custom.png)

如果用户心里有一个具体的人——可能是已故的亲人、远方的故人、失联的朋友——文生图无法准确还原那个人的样貌。图生图解决的就是这个：上传一张照片，AI 保留人物的关键特征（性别、年龄段、五官、发型、神态），把照片转成日漫立绘风格。这一步是 Lumora "思念具象化"叙事的技术起点：从一张真实的照片，到一个可以再次对话的存在。Lumora 不做完美复刻，但会保留足以让用户认出"这就是 ta"的特征。

### 7.4 精灵唤醒界面

![Spirit Awakening](screenshots/04-spirit-awakening.png)

精灵生成完成后，会进入一个短暂的"唤醒"界面——这是 Lumora 仪式感的关键一帧。精灵立绘刚刚显示，但还没有开始对话，像是 ta 刚从沉睡中睁眼，正在适应这个被重新赋予的存在。这一帧不是技术上的过渡，而是叙事上的必要停顿：让用户从"我在创建一个东西"切换到"ta 在这里"。新自定义精灵（如截图中的罗罗）会先经过这一步，再进入正式的房间与聊天流程。

### 7.5 聊天页

![Chat](screenshots/05-chat.png)

精灵房间。左侧是精灵立绘（支持图层分解眨眼、双 player 无缝循环视频、鼠标 reaction、perspective tilt），右侧是对话气泡与输入框。用户说话后，后台会按需检索记忆（tag 预筛 + LLM rerank，默认 top-K=5，深度模式 K=8）注入 system prompt，精灵的回复会自然命中 seed 记忆——例如用户说"我刚路过那家奶茶店了"，精灵会回复"半糖去冰对吧"。顶栏右侧的书本图标是记忆编辑入口，用户可以随时补一条想让 ta 记住的事，下一轮对话立即生效。

### 7.6 精灵记忆编写界面

![Memory Editor](screenshots/06-memory-editor.png)

从聊天页书本图标进入，或创建精灵时的 onboarding 阶段。这一页让用户在 App 内 DIY 记忆，不需要像程序员一样手写 md 文件。上方是 `ta 对你的整体印象`（写入 L1 profile.md），下方是多张记忆卡片（写入 L2 seed events），每张卡片支持标题、内容、标签、重要度（低/中/高）。默认 3 张空卡，最多 15 张，可跳过。seed memories 永不沉睡（permadormant=true），不会被遗忘机制标 dormant。保存后下一轮对话检索自动生效，用户可以随时回来新增、编辑、删除——记忆不是一次写死的，而是会随着相处继续长出新的。

## 8. 非目标 / 明确不做

- **不做完美复刻**：精灵会模糊、会反问、会遗忘。完美记忆是去人化的标志。
- **不做长期养成进度**：没有等级、没有解锁、没有"相处天数"成就。养成进度机制会与"希望你不再需要我"冲突。
- **不做 3D 实时建模**：v1.x 用预生成视频 + 图层分解，3D 留待 v2 评估。
- **不做多人协作**：一个精灵只属于一个用户，不共享。
- **不做云端同步**：所有数据本地存储，符合"私密容器"定位。

## 10. 风险与边界

| 风险 | 应对 |
|---|---|
| 用户把精灵当成真人，拒绝放下 | 北极星 + 不抱怨冷落 + 焦点朝外，引导用户朝真实生活 |
| 完美记忆导致去人化 | 检索 K=5 + 遗忘机制 + 模糊反问 prompt 规则 |
| 用户编造危险内容（自杀教唆等） | 危机拦截 + 宪法 + Boundaries |
| 自定义精灵污染 demo 身份 | prompt 隔离 + smoke test [7/7] |
| API key 泄露 | .gitignore 排除 *.txt + 私有配置目录 |
